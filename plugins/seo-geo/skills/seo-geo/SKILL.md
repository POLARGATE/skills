## 4. Stack Intelligence: Lovable / Vite / React Reality Check

Lovable generates **Vite + React + TypeScript + Tailwind + shadcn/ui** SPAs. By default, this is **client-side rendered**, which is the single biggest SEO vulnerability of the stack. The skill must always start by confirming the rendering model and prescribing the right fix.

### 4.1 Lovable default behavior (as of 2026)

- Single `index.html` shell, all routing handled client-side via React Router.
- Meta tags in `index.html` are static and **the same for every route** unless explicitly overridden.
- No SSR, no SSG, no prerender by default.
- Open Graph tags exist but rarely vary per page.
- No automatic sitemap, no automatic robots.txt unless instructed.
- Default deploy target: Lovable hosting (acceptable) or Vercel / Netlify (preferred for control).

### 4.2 Hard truths about SPA SEO in 2026

- Googlebot **does** render JavaScript, but with delay (second wave of indexing) and quota limits. Critical content rendered only client-side is at risk.
- Bing, Yandex, DuckDuckGo, and most AI crawlers (GPTBot, ClaudeBot, PerplexityBot, Google-Extended) render JS poorly or not at all.
- Per-route meta tags injected via `react-helmet-async` work for Google **only after JS executes**. Social platforms (Facebook, LinkedIn, Slack, X, WhatsApp) often do **not** execute JS, so OG previews break unless meta tags are present in the initial HTML.
- AI crawlers for GEO (GPTBot, ClaudeBot, PerplexityBot) usually fetch raw HTML. CSR sites are largely invisible to them.

**Conclusion**: Pure CSR is acceptable only for authenticated app surfaces. For any public, SEO-relevant page (landing, blog, marketing, product, pricing, about, contact, legal), **prerender or SSG is mandatory**.

### 4.3 The Lovable + Vite SEO upgrade ladder

Pick the lowest rung that fully covers the use case. Always justify the choice.

| Rung | Strategy | Tool | When |
|---|---|---|---|
| 0 | Rich `index.html` only | Manual | Tiny single-page landing, no routes |
| 1 | Per-route meta via Helmet + static prerender | `vite-plugin-prerender` or `vite-plugin-ssg` or `react-snap` | Marketing site, blog, up to ~500 routes, content rarely changes |
| 2 | Static Site Generation | `vite-plugin-ssg`, `vite-react-ssg`, or migrate to Astro / Next.js | Content site, blog, docs, marketing with frequent rebuilds |
| 3 | Server-Side Rendering | Migrate to **Next.js** (App Router) or Remix | Dynamic content, auth-aware SEO, large catalogs, programmatic SEO |
| 4 | Hybrid (ISR + SSG + SSR) | Next.js on Vercel | Ecommerce, SaaS marketing + app, multilingual at scale |

If user is on Lovable and needs Rung 3 or 4: prescribe migration plan, not patches.

### 4.4 Lovable-specific landmines (detect and fix on every audit)

1. Default `<title>` and meta description identical across routes.
2. Default favicon is the Lovable logo. Replace.
3. `index.html` lang attribute hardcoded to `en`. Set to actual language.
4. `viewport` meta missing `viewport-fit=cover` (matters on iOS notch).
5. Open Graph image hardcoded to a placeholder. Replace with branded 1200x630.
6. `react-router` not configured for `<Helmet>` async. Each route fails to update title.
7. No `robots.txt`, no `sitemap.xml`, no `humans.txt`, no `llms.txt`.
8. Supabase data fetched client-side with no fallback HTML. Invisible to crawlers.
9. Images served as PNG/JPG with no `loading="lazy"`, no `width`/`height`, no AVIF/WebP.
10. No `<link rel="canonical">` per route.
11. No structured data (Organization, WebSite, BreadcrumbList missing).
12. Tailwind classes inflate critical CSS. Purge config wrong, render-blocking CSS hits LCP.
13. `vite.config.ts` missing `build.cssCodeSplit`, missing `rollupOptions.output.manualChunks`.
14. Fonts loaded from Google Fonts with no `font-display: swap`, no preload, blocks LCP.
15. shadcn/ui dialogs and popovers introducing CLS via late-mount.
16. Hero image is a video or GIF with no poster, blocking LCP.
17. SPA navigation (`<a href>` replaced by `<Link>`) blocks crawler-friendly link discovery only when prerender is missing.

## 6. Severity-Tiered Audit Framework

Every issue must be tagged with a severity. Use this exact taxonomy:

- **P0 BLOCKER**: Site or page is invisible to search, deindexed, or actively penalized. Examples: `Disallow: /` in robots, accidental sitewide `noindex`, broken canonical pointing offsite, manual action.
- **P1 CRITICAL**: Major loss of organic traffic, ranking, or conversion. Examples: SPA with no prerender on key pages, missing structured data on commercial pages, INP > 500ms on revenue pages, broken hreflang, duplicate-content cannibalization.
- **P2 HIGH**: Material limitation on growth ceiling. Examples: thin content, weak internal linking, slow LCP, missing OG images, missing Organization schema, no llms.txt for AI search.
- **P3 MEDIUM**: Quality and best-practice gaps. Examples: missing breadcrumbs schema, image alt text gaps, sitemap not pinged, no FAQ schema where applicable.
- **P4 LOW**: Polish. Examples: humans.txt missing, security.txt missing, favicon set incomplete, mild meta description rewrites.

Always present audit results sorted P0 to P4. Always include effort estimate (S/M/L) and impact estimate (S/M/L) per item.

## 7. Crawlability and Indexability Playbook

### 7.1 robots.txt (production template)

```txt
# /public/robots.txt
User-agent: *
Allow: /

# Block private and utility routes
Disallow: /admin
Disallow: /api/
Disallow: /auth/
Disallow: /reset-password
Disallow: /thank-you
Disallow: /*?utm_*
Disallow: /*?gclid=
Disallow: /*?fbclid=

# AI crawlers: explicit consent, not implicit
# Allow Google AI Overviews and Bing AI by default
User-agent: Google-Extended
Allow: /

User-agent: GPTBot
Allow: /

User-agent: ClaudeBot
Allow: /

User-agent: anthropic-ai
Allow: /

User-agent: PerplexityBot
Allow: /

User-agent: CCBot
Disallow: /

User-agent: Bytespider
Disallow: /

# Sitemap
Sitemap: https://www.example.com/sitemap.xml
```

Always confirm AI bot policy with the user. Default for marketing sites: allow citation-grade AI bots (GPTBot, ClaudeBot, PerplexityBot, Google-Extended), block bulk training scrapers (CCBot, Bytespider) unless the user wants maximum reach.

### 7.2 Robots meta and X-Robots-Tag

- Public marketing pages: nothing or `<meta name="robots" content="index, follow, max-image-preview:large">`
- Search result pages, filter pages, internal-only: `noindex, follow`
- Auth pages, thank-you pages, internal dashboards: `noindex, nofollow`
- PDFs and non-HTML assets that should not rank: set `X-Robots-Tag: noindex` at server / Vercel headers

### 7.3 Indexation triage

If `Search Console > Pages > Not indexed`:

| Reason | Cause | Fix |
|---|---|---|
| Discovered, not indexed | Low quality or low priority | Improve content, internal links |
| Crawled, not indexed | Quality / duplication signal | Differentiate, add depth, fix canonicals |
| Soft 404 | Empty or near-empty page | Add real content or noindex |
| Duplicate, no canonical | Multiple URLs same content | Set canonical, consolidate |
| Page with redirect | URL changed | Update internal links to final URL |
| Excluded by noindex | Intentional or accidental | Verify, remove if accidental |
| Blocked by robots.txt | Disallow rule | Fix robots if unintentional |
| Server error 5xx | Hosting issue | Investigate logs, fix |

## 8. Rendering Strategy Decision Tree

```
Is the page public and SEO-relevant?
├─ NO → CSR is fine (private app)
└─ YES
   ├─ Does content change rarely (≤ daily)?
   │  └─ YES → Static prerender (Rung 1) or SSG (Rung 2)
   ├─ Does content change frequently (hourly) or is user-personalized for SEO?
   │  └─ YES → SSR or ISR (migrate to Next.js, Rung 3-4)
   └─ Is the catalog huge (> 10k pages, programmatic)?
      └─ YES → Hybrid SSG + ISR (Next.js, Rung 4)
```

For Lovable users specifically:

- < 50 routes, marketing site → install `vite-plugin-prerender-spa` or `vite-react-ssg`
- 50 to 5k routes, blog or content site → migrate to Astro or Next.js (App Router, SSG)
- Anything dynamic, ecommerce, multilingual at scale → Next.js on Vercel

## 9. Metadata System (production-ready React component)

### 9.1 Per-route SEO component

```tsx
// src/components/SEO.tsx
import { Helmet } from "react-helmet-async";

type SEOProps = {
  title: string;
  description: string;
  canonical: string;
  image?: string;
  type?: "website" | "article" | "product";
  locale?: string;
  alternates?: { hrefLang: string; href: string }[];
  noindex?: boolean;
  publishedTime?: string;
  modifiedTime?: string;
  author?: string;
  jsonLd?: Record<string, unknown> | Record<string, unknown>[];
};

const SITE_NAME = "Acme";
const TWITTER_HANDLE = "@acme";
const DEFAULT_IMAGE = "https://www.acme.example/og/default-1200x630.jpg";

export function SEO({
  title,
  description,
  canonical,
  image = DEFAULT_IMAGE,
  type = "website",
  locale = "en_US",
  alternates = [],
  noindex = false,
  publishedTime,
  modifiedTime,
  author,
  jsonLd,
}: SEOProps) {
  const fullTitle = title.includes(SITE_NAME) ? title : `${title} | ${SITE_NAME}`;
  const robots = noindex ? "noindex, nofollow" : "index, follow, max-image-preview:large, max-snippet:-1";
  const ldArray = Array.isArray(jsonLd) ? jsonLd : jsonLd ? [jsonLd] : [];

  return (
    <Helmet>
      <html lang={locale.split("_")[0]} />
      <title>{fullTitle}</title>
      <meta name="description" content={description} />
      <meta name="robots" content={robots} />
      <link rel="canonical" href={canonical} />

      {/* Open Graph */}
      <meta property="og:site_name" content={SITE_NAME} />
      <meta property="og:title" content={fullTitle} />
      <meta property="og:description" content={description} />
      <meta property="og:url" content={canonical} />
      <meta property="og:type" content={type} />
      <meta property="og:image" content={image} />
      <meta property="og:image:width" content="1200" />
      <meta property="og:image:height" content="630" />
      <meta property="og:locale" content={locale} />

      {/* Twitter */}
      <meta name="twitter:card" content="summary_large_image" />
      <meta name="twitter:site" content={TWITTER_HANDLE} />
      <meta name="twitter:title" content={fullTitle} />
      <meta name="twitter:description" content={description} />
      <meta name="twitter:image" content={image} />

      {/* Article-specific */}
      {publishedTime && <meta property="article:published_time" content={publishedTime} />}
      {modifiedTime && <meta property="article:modified_time" content={modifiedTime} />}
      {author && <meta name="author" content={author} />}

      {/* Hreflang */}
      {alternates.map(({ hrefLang, href }) => (
        <link key={hrefLang} rel="alternate" hrefLang={hrefLang} href={href} />
      ))}
      {alternates.length > 0 && (
        <link rel="alternate" hrefLang="x-default" href={alternates[0].href} />
      )}

      {/* JSON-LD */}
      {ldArray.map((ld, i) => (
        <script key={i} type="application/ld+json">
          {JSON.stringify(ld)}
        </script>
      ))}
    </Helmet>
  );
}
```

### 9.2 Title and description rules

- Title: 50 to 60 characters, primary keyword first, brand last, no clickbait, no ALL CAPS.
- Description: 140 to 160 characters, action-oriented, contains primary keyword and a benefit, ends with implicit CTA.
- Never duplicate title or description across pages. Auto-generated should still vary by entity (city, product, category).
- For programmatic pages, use template + variable, never raw boilerplate.

### 9.3 Canonical rules

- Always absolute URL, https, lowercase, no trailing slash inconsistency, no query strings unless they define content.
- Self-canonical on every public page.
- Cross-canonical only when content is truly duplicated and consolidated.
- Never canonical to a redirected URL or a 404.

### 10.9 Person (author pages, E-E-A-T)

Required for blog authors to signal expertise. Include `jobTitle`, `sameAs` (LinkedIn, Twitter, Wikipedia, ORCID), `knowsAbout`.

### 10.10 Validation

Always validate with: Google Rich Results Test, Schema.org validator (validator.schema.org), Search Console > Enhancements after deploy.

## 11. Sitemap and Robots Generators

### 11.1 sitemap.xml strategy

- One sitemap if < 50k URLs and < 50MB.
- Sitemap index if larger or split by type (pages, blog, products, images).
- Include only canonical, indexable, 200-status URLs.
- Include `lastmod` (real timestamp, not build time placeholder).
- Submit in Search Console and Bing Webmaster Tools.
- Reference in robots.txt.

### 11.2 Vite build-time sitemap generator

Use `vite-plugin-sitemap` or write a postbuild script that walks the route manifest. Sample postbuild (Node):

```ts
// scripts/generate-sitemap.ts
import { writeFileSync } from "node:fs";
import { join } from "node:path";

const SITE = "https://www.example.com";
const routes = [
  { loc: "/", lastmod: "2026-05-07", changefreq: "weekly", priority: 1.0 },
  { loc: "/about", lastmod: "2026-04-01", changefreq: "monthly", priority: 0.7 },
  { loc: "/pricing", lastmod: "2026-05-05", changefreq: "weekly", priority: 0.9 },
  { loc: "/blog", lastmod: "2026-05-07", changefreq: "daily", priority: 0.8 },
];

const xml = `<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
${routes
  .map(
    (r) => `  <url>
    <loc>${SITE}${r.loc}</loc>
    <lastmod>${r.lastmod}</lastmod>
    <changefreq>${r.changefreq}</changefreq>
    <priority>${r.priority}</priority>
  </url>`
  )
  .join("\n")}
</urlset>`;

writeFileSync(join("dist", "sitemap.xml"), xml, "utf8");
console.log("sitemap.xml generated");
```

Wire into `package.json`: `"build": "vite build && tsx scripts/generate-sitemap.ts"`.

### 11.3 Image and video sitemaps

Use when the site relies on visual content (ecommerce, real estate, portfolio, recipes). Include image `<image:loc>`, `<image:caption>`, `<image:title>`.

## 12. Core Web Vitals Playbook (INP-first, 2026 standard)

CWV thresholds (Google, current):

| Metric | Good | Needs Improvement | Poor |
|---|---|---|---|
| LCP | ≤ 2.5s | ≤ 4.0s | > 4.0s |
| INP | ≤ 200ms | ≤ 500ms | > 500ms |
| CLS | ≤ 0.1 | ≤ 0.25 | > 0.25 |

Field data (CrUX) wins over lab data. Always check both.

### 12.1 LCP fixes (highest leverage)

1. Identify LCP element: usually hero image, hero text, or hero video.
2. Preload hero image: `<link rel="preload" as="image" href="/hero.avif" fetchpriority="high">`.
3. Use `<img fetchpriority="high" loading="eager" decoding="async">` on the LCP image only. Lazy everything else.
4. Serve modern formats: AVIF first, WebP fallback, JPG last. Use `<picture>`.
5. Specify `width` and `height` to prevent layout shift.
6. Self-host fonts. Preload the single font weight used above the fold. Use `font-display: swap`.
7. Eliminate render-blocking CSS. Tailwind purge must be aggressive. Inline critical CSS for above-the-fold if needed.
8. Cache aggressively: `Cache-Control: public, max-age=31536000, immutable` for hashed assets.
9. Use a CDN with edge caching (Vercel, Cloudflare, Netlify).

### 12.2 INP fixes (critical for interactive sites)

INP measures the worst interaction delay during a session. Common offenders:

1. Heavy click handlers on buttons (e.g., dispatching large state updates).
2. Synchronous `localStorage` / `sessionStorage` reads on click.
3. Re-rendering large component trees on input.
4. Third-party scripts (chat widgets, analytics) hijacking the main thread.

Fixes:

- Wrap expensive state updates in `startTransition` (React 18+).
- Use `useDeferredValue` for inputs that drive heavy lists.
- Memoize with `React.memo`, `useMemo`, `useCallback` where measured.
- Defer third-party scripts: load on idle, on interaction, or on viewport.
- Use Web Workers for computation > 50ms.
- Audit with PageSpeed Insights Field Data + Chrome DevTools Performance Insights.

### 12.3 CLS fixes

1. Always set `width` / `height` or `aspect-ratio` on images, videos, iframes, ads.
2. Reserve space for dynamic content (skeletons, fixed-height containers).
3. Avoid late-injected banners, cookie bars without reserved space, web fonts swapping with size mismatch.
4. shadcn/ui dialogs and toasts: ensure portal mounts do not push content. Use `position: fixed`.

### 12.4 Vite performance config

```ts
// vite.config.ts
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react-swc";
import { compression } from "vite-plugin-compression2";
import { imagetools } from "vite-imagetools";

export default defineConfig({
  plugins: [
    react(),
    imagetools(),
    compression({ algorithm: "brotliCompress" }),
    compression({ algorithm: "gzip" }),
  ],
  build: {
    target: "es2020",
    cssCodeSplit: true,
    sourcemap: false,
    minify: "esbuild",
    rollupOptions: {
      output: {
        manualChunks: {
          react: ["react", "react-dom"],
          router: ["react-router-dom"],
          ui: ["@radix-ui/react-dialog", "@radix-ui/react-popover"],
        },
      },
    },
  },
});
```

## 13. Image and Asset Optimization

- **Format**: AVIF > WebP > JPG/PNG. Provide `<picture>` with multiple sources.
- **Dimensions**: never serve oversized. Use `srcset` with breakpoints (320, 640, 960, 1280, 1920).
- **Lazy loading**: `loading="lazy"` on everything below the fold. `loading="eager"` on hero only.
- **Decoding**: `decoding="async"` on non-critical images.
- **CDN with image transforms**: Vercel Image, Cloudflare Images, Cloudinary, imgix. Avoid hand-cropping.
- **Alt text**: descriptive, not stuffed. Empty `alt=""` only for decorative.
- **SVG**: inline for icons used multiple times. External `<img>` for one-off illustrations.
- **Fonts**: subset, self-host, preload one weight, `font-display: swap`. Use variable fonts when possible.
- **Videos**: never autoplay above the fold without `poster`. Use `<video preload="metadata">`.
- **Icons**: Lucide React (already in Lovable stack) is tree-shakable. Avoid full icon libraries imported at root.

## 14. Internal Linking Architecture

### 14.1 Principles

- Every important page must be reachable in ≤ 3 clicks from the homepage.
- No orphans (pages with zero internal inbound links).
- No dead ends (pages with zero outbound links to other site content).
- Use **descriptive anchor text** (not "click here", not "read more" alone).
- Vary anchor text naturally across pages linking to the same destination.
- Use breadcrumbs on every page beyond root.
- Use contextual in-content links (highest value), not just nav and footer.

### 14.2 Hub-and-spoke (topical authority)

For content sites and blogs:

- **Pillar page**: comprehensive, 2000+ words, targets head term.
- **Cluster pages**: 800 to 1500 words each, target long-tails, all link back to pillar with anchor variations, link to peer cluster pages where relevant.
- **Pillar links to all clusters**, ideally in a structured TOC.

### 14.3 Anchor text rules

- Branded: "Acme"
- Exact match: "SEO for React apps"
- Partial match: "this React SEO guide"
- Generic: "this article" (use sparingly)
- Naked URL: rare, not preferred

Distribute: 20% branded, 30% partial, 20% exact, 20% topical, 10% generic. Never over-optimize exact match.

## 15. International SEO and hreflang

### 15.1 URL structure decision

| Option | Best for | Pros | Cons |
|---|---|---|---|
| ccTLD (`example.de`) | Strong country signal, separate brands per country | Strongest geo signal | Most expensive, splits authority |
| Subfolder (`example.com/de/`) | Most SaaS, content sites | Authority consolidates, easy to manage | Weaker geo signal |
| Subdomain (`de.example.com`) | Edge cases, separate infra | Geo signal | Treated as separate site |

Default recommendation: **subfolder** unless there is a strong business reason otherwise.

### 15.2 hreflang implementation

- Every localized page must list **all** language variants including itself.
- Use ISO 639-1 language and ISO 3166-1 alpha-2 region codes: `en`, `en-US`, `en-GB`, `es`, `es-MX`, `nl`.
- Always include `x-default` pointing to the language selector or default version.
- Implement in `<head>` per-page or in XML sitemap. Avoid HTTP headers unless server-rendered.

### 15.3 Common hreflang errors (Search Console will flag)

- Return-tag missing (page A links to B, B does not link back to A).
- Wrong region code.
- Pointing to non-canonical URL.
- Pointing to redirected URL.
- Pointing to noindex page.

### 15.4 Localization beyond translation

- Currency, units, date formats per locale.
- Local case studies, testimonials, logos.
- Local schema (LocalBusiness, addressCountry).
- Local backlinks (local press, partnerships).
- Local hosting region for TTFB.

## 16. AI Search and GEO (Generative Engine Optimization)

This is where 2026 SEO diverges from 2020 SEO. Google AI Overviews, ChatGPT Search, Perplexity, Claude, and Gemini cite sources differently than traditional rankings.

### 16.1 GEO principles

1. **Citation-worthy content**: stats, definitions, original data, named frameworks, expert quotes. AI engines prefer citing sources that introduce verifiable claims.
2. **Entity clarity**: structured data with explicit `@id` linking, Wikipedia-style fact density, named entities.
3. **Direct answers**: lead paragraphs with the answer, then expand. Inverted pyramid.
4. **Q&A structure**: H2 questions, direct answers under them. FAQPage schema where relevant.
5. **Author credibility**: real bylines with `Person` schema, LinkedIn `sameAs`, topical history.
6. **Freshness signals**: visible publish + update dates, `dateModified` in schema.
7. **Original assets**: charts, original studies, datasets, calculators. AI engines preferentially cite original sources.

### 16.2 llms.txt (emerging standard, 2024+)

A new file at site root that tells LLM-based crawlers what to read for accurate summaries.

```txt
# /public/llms.txt
# Acme: aerospace-inspired branding and product platform.

> Acme is a [briefly describe product/positioning in one sentence].

## Core pages
- [Homepage](https://www.example.com): product overview, positioning, primary CTA.
- [Pricing](https://www.example.com/pricing): plans, prices in EUR, feature comparison.
- [About](https://www.example.com/about): team, mission, founding story.

## Documentation
- [Docs](https://www.example.com/docs): full product documentation.
- [API Reference](https://www.example.com/api): technical reference.

## Optional
- [Blog](https://www.example.com/blog): updates and thought leadership.
- [Changelog](https://www.example.com/changelog): release history.
```

Also publish `llms-full.txt` with full markdown content of key pages. Reference: llmstxt.org (community spec).

### 16.3 AI crawler policy in robots.txt

Already covered in 7.1. Default: allow citation-grade bots, optionally block training bots.

### 16.4 Content patterns that get cited

- **Stat-driven openers**: "73% of teams report ..."
- **Named frameworks**: "the X-Y-Z method", coin terms.
- **Comparison tables**: "X vs Y" with crisp criteria.
- **Definitions**: "X is a ..." in the first sentence.
- **Step-by-step guides**: numbered, scannable.
- **Tools and calculators**: indexable interactive widgets.

### 16.5 Track AI citations

- Monitor referrers: `chat.openai.com`, `perplexity.ai`, `bing.com/chat`, `gemini.google.com`.
- Use Profound, Otterly, AthenaHQ, or manual monitoring.
- Track branded query mentions in AI engines weekly.

## 18. Accessibility as SEO

WCAG 2.2 AA is both ethical and SEO-relevant. Google uses signals correlated with accessibility (semantic HTML, alt text, contrast, mobile usability).

### 18.1 Non-negotiables

- Semantic HTML: `<header>`, `<nav>`, `<main>`, `<article>`, `<section>`, `<aside>`, `<footer>`.
- One `<h1>` per page, hierarchical headings, no skipping levels.
- All images have `alt`. Decorative use `alt=""`.
- All interactive elements keyboard-accessible. Focus visible.
- Color contrast: 4.5:1 for text, 3:1 for large text and UI.
- Touch targets: 44x44 px minimum.
- Form labels properly associated, error messages announced.
- ARIA only when native HTML is insufficient. Prefer native.
- `prefers-reduced-motion` respected.
- Language declared, language changes annotated with `lang`.

### 18.2 Tools

- axe DevTools, Lighthouse Accessibility, WAVE.
- Manual: keyboard-only navigation, screen reader (VoiceOver, NVDA).

## 19. Content Strategy Framework

### 19.1 Search intent taxonomy

| Intent | Examples | Page type |
|---|---|---|
| Informational | "what is X", "how to Y" | Blog, guide, glossary |
| Commercial investigation | "best X", "X vs Y", "X review" | Comparison, review, listicle |
| Transactional | "buy X", "X pricing" | Product, pricing, signup |
| Navigational | "Brand login", "Brand careers" | Branded pages |

Match content type to intent. Misalignment is the most common ranking failure.

### 19.2 Content brief template

For every target query, produce:

- Primary query and search volume
- Search intent
- Top 3 competing URLs and their gaps
- Target word count (median of top 3, ±20%)
- Required H2/H3 outline
- Required entities (people, products, concepts)
- Required schema types
- Internal links in (5 to 10 from related pages)
- Internal links out (3 to 7 to related pages)
- External links out (2 to 5 to authoritative sources)
- CTAs and conversion path
- Author with E-E-A-T credentials
- Update cadence

### 19.3 Content quality bar (E-E-A-T)

- **Experience**: real first-person experience or original data.
- **Expertise**: author with credentials, schema-linked.
- **Authoritativeness**: cited by others, on-topic backlinks.
- **Trustworthiness**: HTTPS, privacy policy, contact info, transparent ownership, no misleading claims.

For YMYL (Your Money or Your Life) topics: medical, financial, legal, safety. The bar is higher. Real expert authorship is mandatory.

### 19.4 Content refresh

- Quarterly: review top 50 pages by traffic. Update stats, screenshots, CTAs.
- Annually: rewrite or consolidate underperformers. Redirect or noindex thin pages.
- Always update `dateModified` on real edits, not cosmetic.

## 20. Conversion-Aware SEO

Ranking without converting is wasted compute. Every SEO recommendation must consider the conversion path.

### 20.1 Conversion architecture per intent

- **Informational pages**: soft CTA (newsletter, related guide, content upgrade).
- **Commercial pages**: comparative CTAs, social proof, free trial.
- **Transactional pages**: primary CTA above the fold, sticky CTA on scroll, secondary CTAs in content.

### 20.2 Above-the-fold rules

- Clear value proposition in 6 to 12 words.
- Sub-headline expanding the value in 15 to 25 words.
- Primary CTA visible without scroll on mobile and desktop.
- Trust signal nearby (logo bar, rating, customer count).
- LCP element optimized.

### 20.3 Form and CTA optimization

- Minimize required fields. Each field reduces conversion ~5% on average.
- Use single-column forms.
- Inline validation.
- CTA copy: action + outcome ("Start free trial", "Get my SEO audit").
- A/B test only with statistical rigor (n ≥ 1000 conversions, p < 0.05, 2-week minimum).

## 21. Anti-Patterns to Detect and Kill

When auditing, look for and flag these immediately:

1. Default Lovable / Vite metadata across all routes.
2. Duplicate H1s within a page or identical H1s across pages.
3. Pagination with no `rel="canonical"` self-reference and no view-all canonical.
4. Internal search results pages indexed (`/search?q=...`).
5. Faceted navigation generating infinite indexable URLs (color, size, sort).
6. Soft 404s (empty states returning 200).
7. Hash-based routing on public pages (`/#/about`). Crawlers see one page.
8. Lazy loading the LCP element.
9. Cookie banner blocking content for crawlers (some bots respect this and bounce).
10. Hidden content on tabs/accordions where it is the only place keyword appears (acceptable for UX, but ensure crawlable HTML).
11. Carousel as the only place for hero content (rotate-killing crawlers).
12. Auto-translated content with no `hreflang`, no editorial review.
13. AI-generated content with zero human review, no schema, no original data.
14. Backlink schemes (PBNs, paid links without `nofollow`/`sponsored`).
15. Keyword stuffing in alt text, footer, hidden divs.
16. Schema markup that does not match visible page content.
17. Reviews schema on pages with no actual visible reviews.
18. Multiple analytics scripts firing the same event (double-counting).
19. Mixed protocol assets (http on https page).
20. Trailing-slash inconsistency (some pages with, some without).
21. Indexable staging environments (`staging.example.com` not blocked).
22. CDN edge caching the wrong content (vary headers wrong).

```
13. Add BreadcrumbList schema where applicable.
14. Verify Lighthouse SEO ≥ 100, Accessibility ≥ 95, Performance ≥ 90 mobile.
15. No regressions in existing UX. Maintain Tailwind / shadcn / TypeScript conventions.
```

### 25.3 When to migrate off Lovable

Migrate to **Next.js (App Router on Vercel)** when any of the following is true:

- More than 5,000 routes (programmatic SEO).
- Server-rendered, personalized SEO content needed.
- Multilingual at scale with locale-aware rendering.
- Ecommerce with dynamic pricing and stock.
- Heavy editorial CMS integration (Contentful, Sanity, Payload).
- INP / LCP cannot be salvaged without server rendering.

Migrate to **Astro** when:

- Content-heavy site (blog, docs, marketing).
- Minimal interactivity outside of islands.
- Maximum performance with minimum JS.
